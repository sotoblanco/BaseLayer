# Build-Project Mode

## Overview

Build-Project mode enables course authors to design sequential multi-step projects where each step contributes to and accumulates one working artifact. Instead of disconnected coding exercises that run in total isolation, each project step builds directly on top of the artifacts generated by prior steps.

## Key Concepts

### 1. Project Manifest and Step Contracts

A course is declared as a project by including a `project.json` file in the course root or specifying `"is_project": true` in the course root `metadata.json`.

Each step in a project defines two optional contract properties:
- `consumes`: An array of artifact filenames required by this step (for example, `["dataset.csv"]`).
- `produces`: The filename of the artifact created upon successfully completing this step (for example, `"scaled_data.py"`).

Contracts can be defined either centrally in the `steps` array of `project.json` or per-lesson in each lesson directory's `metadata.json`.

Example `project.json`:
```json
{
  "is_project": true,
  "title": "Tabular Data Pipeline",
  "description": "Build an end-to-end data processing and prediction pipeline that accumulates artifacts across 3 connected steps.",
  "skills": ["data-pipeline", "feature-scaling", "linear-regression"],
  "steps": [
    {
      "slug": "step01-ingest",
      "consumes": [],
      "produces": "dataset.csv"
    },
    {
      "slug": "step02-scale",
      "consumes": ["dataset.csv"],
      "produces": "scaled_data.py"
    },
    {
      "slug": "step03-predict",
      "consumes": ["dataset.csv", "scaled_data.py"],
      "produces": "predictions.csv"
    }
  ]
}
```

### 2. User Artifact Storage and Isolation

Artifacts generated by learners are saved in user-specific storage under:
```
learners/{username}/projects/{course_slug}/{artifact_filename}
```
This isolates each user's working state while preserving files across sessions. Course seed fixtures stored under `courses/{course_slug}/fixtures/` or the course root serve as fallback inputs for courses that provide starter files.

### 3. Execution Workspace Injection

Before code executes for Step N:
1. The backend inspects `consumes` for the current step.
2. If any required consumed artifact has not been produced yet, execution is halted with an error explaining which files are missing and that the step is locked.
3. The backend copies all required consumed artifacts from the user's project storage into the execution workspace (`temp_dir`, mapped to `/app` in Docker).
4. The learner's code executes in the sandbox, with all prior artifacts directly available for import or file operations.

### 4. Verification and Unlocking Semantics

When a learner submits Step N (`is_submit: true`):
1. The sandbox tests are executed.
2. If tests pass, the backend verifies that the declared `produces` artifact exists in the workspace.
3. If the declared artifact is missing, verification fails with exit code 1 and a descriptive message: `Verification failed: required artifact '{produces}' was not produced.`
4. If tests pass and the declared artifact is present, the artifact is saved to the user's project storage.
5. The completion event is recorded in `LEARNING.md`, immediately unlocking Step N+1.

### 5. Player Locking UI and Catalog Badging

- **Catalog Badging**: Project courses display an amber `Project` badge alongside `Curated`/`Generated` in the course catalog.
- **Ordered Lockable Chain**: The player displays lock icons on steps whose prerequisite artifacts have not yet been produced.
- **Navigation Guards**: Learners cannot click into or navigate forward into locked steps until all consumed artifacts have been generated.
- **Dynamic Refresh**: When a learner successfully submits a passing step, the player automatically refreshes the course outline and unlocks the subsequent step.

## Tabular Pipeline Fixture

A reference 3-step project course is provided at `courses/tabular-project/`:
1. `chapter1/step01-ingest`: Ingests raw data points and writes `dataset.csv`.
2. `chapter1/step02-scale`: Consumes `dataset.csv`, normalizes feature values, and writes a reusable module `scaled_data.py`.
3. `chapter1/step03-predict`: Consumes `dataset.csv` and `scaled_data.py`, runs linear predictions, and writes `predictions.csv`.
